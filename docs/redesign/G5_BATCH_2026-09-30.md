## Architecture and privacy

- `job_application_workflows` is product storage, not analytics. Browser roles have no direct table/function access; server functions derive owner identity from the verified token.
- Workflow writes accept a bounded closed vocabulary, reject controls/oversize content and past opt-in dates, serialize first writes, and require the expected revision. Only decision/status/timestamp enter the capped 100-row history; notes/contact details never do.
- Outbound analytics receives only closed decision/status tokens and never job/resume text, IDs, notes, contacts, dates or URLs.
- Account load fails soft if the new workflow migration is unavailable; saved jobs, Match and job-specific resumes remain usable while workflow writes are disabled.
- Private routes/noindex, safe UUID URLs, master-resume separation, saved-job ownership and existing download/conversion boundaries are unchanged.
