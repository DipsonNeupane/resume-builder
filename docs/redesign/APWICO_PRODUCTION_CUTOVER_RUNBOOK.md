# APWICO production cutover runbook

Prepared 2026-10-01 for the isolated redesign candidate. This is a rehearsal artifact, not release authorization. Do not put secrets, tokens, customer data or resume/job content in this document, tickets, chat or command output.

## Release controls

- One named owner authorizes the window, rollback threshold and redirect activation in writing.
- Freeze one commit and one built artifact. Record commit, migration manifest, deployment ID and configuration-name inventory; never export secret values.
- Keep `BRAND_DOMAIN_REDIRECTS_ENABLED=false` and `BRAND_PERMANENT_REDIRECTS_ENABLED=false` through deployment and APWICO smoke testing. Redirect activation is a distinct, later action.
- Keep `resumestride.com` and its TLS active throughout the monitoring window. Never recreate Supabase, Stripe customers/subscriptions, local-storage keys or database identifiers for branding.
- Stop on an unexpected migration, redirect chain/loop, cross-owner read, failed cancellation, invalid webhook, missing recovery email, or loss of browser-only work.

## Pre-cutover

1. Resolve every “required before production” item in `FINAL_PRE_RELEASE_REHEARSAL_2026-10-01.md`.
2. Approve local-state coexistence duration, legal/provider copy, release window, rollback owner and acceptable recovery point/time.
3. Reconcile hosted migration history and catalog to the frozen source. Take a current provider-supported recovery point and prove a populated isolated restore; never restore over production as a drill.
4. Run `npm run quality:gate`, `npm run test:server`, `npm run test:db`, `npm run test:auth`, `npm run test:paid`, `npm run test:extension`, package checks, dependency audit and brand check on the frozen commit.
5. Prepare provider changes above, with redirects/new aliases not yet serving users.

## Deployment and domain validation

1. Deploy the frozen artifact to the existing project with redirect flag false and gates matching the approved plan.
2. Attach APWICO as an additional host, validate TLS, headers, canonical assets and provider callbacks before changing the old domain.
3. Run APWICO smoke tests: all three entry journeys; matcher/sample; import/builder; saved jobs/Match/version/export; pricing/trust; auth/recovery; manual application state; public SEO; narrow viewport/keyboard; ownership/privacy.
4. Run old-origin compatibility with a fictional local draft and two synthetic accounts. Do not use real resume/job content.

## Redirect activation

Only after explicit authorization, enable the temporary redirect flag first. Verify old apex/`www` and representative public/private/missing paths plus old-tab API writes. Preserve path/query, keep missing paths missing, and confirm APWICO has no self-redirect. Promote to the separately gated 301 only after the coexistence window and monitoring pass.

## Post-cutover verification and monitoring

- Re-run HTTP, browser, auth/recovery, billing return/webhook, email-link, export and owner-isolation checks.
- Monitor 5xx/error categories, webhook failures, auth delivery, checkout cancellation, conversion discontinuity, 404s/redirect chains, Search Console coverage and field performance. Do not log payloads.
- Keep ResumeStride domain/TLS, old provider callbacks and exact extension compatibility for the approved window.
- Treat Tasks 58–61, translated launches and published extension work as Optional / post-launch, not cutover gates.

## Rollback procedure

1. Freeze new sales/writes only through existing reversible gates needed to protect data; keep cancellation and support available.
2. Set both redirect flags false and restore the last verified domain/alias target. Temporary 307s are no-store; after permanent promotion, allow for the bounded five-minute cache policy and uncontrolled intermediary/DNS variance.
3. Redeploy the last known ResumeStride artifact if application rollback is needed. Do not reverse database migrations with destructive SQL; apply a reviewed forward repair.
4. Restore prior callback/return/sender URLs only where the old artifact needs them, retaining both domains until sessions settle.
5. Confirm owner isolation, entitlement/customer/subscription references, existing data and support access; record the incident without content or secrets.

## Responsibility split

- **Agent after authorization:** freeze/build/deploy the candidate, run migrations exactly as reconciled, run smoke/compatibility/monitoring checks, toggle the existing redirect flag only when specifically authorized, and execute the documented rollback.
- **Owner login / approval:** DNS/registrar, production Vercel alias approval, Supabase/Auth/email, Stripe business-facing settings, Search Console, analytics account settings, recovery spend, release window, local-state retention window and final redirect/cutover authorization.
- **Optional / post-launch:** Tasks 58–61, extension publication (Task 37), broader localization, partnerships, research publication, outcome claims and demand/field-performance optimization.
